## Files to change

**Version note:** the current Astro is **7.4.3** (`@astrojs/mdx` 8.1.2, `@astrojs/sitemap` 3.7.4,
ESLint 10.13, `eslint-plugin-astro` 3.2.1). The spec's design says "Astro 5". No requirement names
a version, and the pieces the design uses (`src/content.config.ts` with the `glob` loader,
`getStaticPaths`, `astro:assets` `getImage`, built-in Shiki) are all current API, so this plan
uses Astro 7. The spec's Design line gets corrected at ship.

**New**
- `package.json` (rewritten): `type: module`, `engines.node: ">=24"`, and these scripts:
  - `dev`, `preview`, `format`;
  - `build` = `astro check && astro build`;
  - `lint` = `eslint . && prettier --check .`;
  - `check:urls`, `check:dist`.
  Dependencies are astro, @astrojs/mdx, @astrojs/sitemap, @astrojs/check, typescript, lodash,
  @fontsource/bitter and @fontsource/open-sans. Dev dependencies are eslint, @eslint/js,
  typescript-eslint, eslint-plugin-astro, prettier and prettier-plugin-astro.
- `package-lock.json` (regenerated by `npm install`), `.nvmrc` (`24`).
- `astro.config.mjs`: `site`, `output: 'static'`, `build.format: 'directory'`,
  `trailingSlash: 'ignore'`, `integrations: [mdx(), sitemap()]`, and Shiki theme `dark-plus`
  (the closest match to prism's vsDark).
- `tsconfig.json` (extends `astro/tsconfigs/strict`), `eslint.config.js`, `.prettierrc`
  (no semis, single quotes, width 120, as in the old `.eslintrc` prettier rule), and
  `.prettierignore` (`blog/`, `dist/`, `.astro/`, `.sdlc/`, `*.md`, lockfiles). Posts are kept
  out of formatting for R14.
- `src/config.ts`: the keys from `config/index.js` minus `googleAnalyticsID`, plus the theme
  values `themeColor` and `backgroundColor`.
- `src/content.config.ts`: a `posts` collection with
  `glob({ pattern: '*/index.mdx', base: './blog' })` and the schema
  `{ date: z.coerce.date(), title: z.string(), categories: z.array(z.string()), slug: z.string().optional() }`.
- `src/lib/posts.ts`:
  - `postPath(entry)` returns `'/' + kebabCase(entry.data.slug ?? entry.data.title)`, using
    `lodash/kebabCase`, the same function `gatsby-node.js` and `Article.js` use (R4);
  - `categoryPath(cat)`;
  - `getSortedPosts()`, newest first, as the `allMdx` queries sorted;
  - `excerpt(body)`: a markdown-to-plain-text strip that drops code fences, JSX/HTML tags,
    link and image syntax, and heading and emphasis marks, collapses whitespace, and truncates
    at 200 characters with `…`, like `excerpt(pruneLength: 200)`;
  - `timeToRead(body)`: `Math.round(words / 265)`, minimum 1, Gatsby's formula;
  - `formatDate(d)`: `MM/DD/YYYY` in UTC, matching `formatString: "MM/DD/YYYY"`.
- `src/styles/global.css`: a port of `createGlobalStyle` in `Layout.js`. The theme
  (`config/theme.js`) becomes `:root` custom properties copied value for value:
  - `--primary: #ff5f5f`;
  - `--primary-light`, `lighten(0.05)` precomputed: `#ff7878`;
  - `--primary-dark` and `--primary-lighter`, `darken`/`lighten(0.1)` for the header gradient,
    precomputed: `#ff2c2c` and `#ff9292`;
  - the four greys, `--max-width: 1000px` and the fonts.
  Breakpoints stay literal (`1200px` and `600px`) in the media queries, since custom properties
  can't be used there.
- `src/layouts/BaseLayout.astro`:
  - in `<head>`: fontsource imports (Bitter 400/700, Open Sans 400/700) and global.css, then
    `<SEO>`;
  - in `<body>`: a slot, then the footer from `Layout.js` (© 2020 line, GitHub and Ko-fi links),
    without Manage Cookies or Last build.
- `src/components/`:
  - `SEO.astro`, a port of `SEO.js`. It outputs the title, description, image, OG and Twitter
    tags and `<link rel="canonical">`, and JSON-LD: `WebSite` on the index; on posts,
    `BlogPosting` (datePublished from frontmatter `date`) plus `BreadcrumbList`. It also adds
    `<link rel="manifest">`, the favicon and `<meta name="theme-color">`, with no Helmet and no
    Metomic.
  - `Header.astro`, `Wrapper.astro`, `Article.astro`, `Subline.astro`, `SectionTitle.astro`,
    `Button.astro` and `PrevNext.astro`: one each, porting the styled-component of the same name
    to markup and a scoped `<style>`.
- `src/pages/`:
  - `index.astro`: Hero with "Hi.", the Contact button with its SVG, and "Latest stories";
  - `[slug].astro`: `getStaticPaths` from `getSortedPosts()`, with prev = the older post and
    next = the newer one, as in `gatsby-node.js`; it calls `render(entry)` and styles the
    content as in `templates/post.js`;
  - `categories/index.astro` (the category list with counts);
  - `categories/[category].astro` (subline "N post(s) tagged with …");
  - `contact.astro`, with the form attributes copied verbatim from `contact.js`, including the
    hidden `form-name` and a hidden `bot-field` input. The old file referenced the honeypot but
    rendered no such field.
  - `success.astro`;
  - `manifest.webmanifest.ts`: a GET endpoint returning name, short_name, description,
    start_url `/`, display `standalone` and the colours from `src/config.ts`. Its icons are
    192 and 512 px PNGs made from `src/favicon.png` with `getImage` (R13).
- `public/`: `static/img`, `static/social` and `static/robots.txt` moved with `git mv`, and
  robots.txt's sitemap line changed to `/sitemap-index.xml`. Also `public/favicon.png` (copied
  from `src/favicon.png`) and a new `public/sw.js`: the kill switch from the spec's design, using
  `skipWaiting`, `caches.keys()` → delete all, `registration.unregister()`, then
  `clients.matchAll({type:'window'})` → `client.navigate(client.url)`.
- `netlify.toml`:
  - `[build] command = "npm run build"`, `publish = "dist"`,
    `[build.environment] NODE_VERSION = "24"`;
  - a `[[headers]]` block for `/sw.js` setting `Cache-Control: no-cache`;
  - a `[[redirects]]` block sending `/sitemap.xml` to `/sitemap-index.xml` with a 301.
- `scripts/expected-urls.txt`: the 15 paths from the live sitemap as of 2026-10-28.
- `scripts/check-urls.mjs`: checks that `dist/<path>/index.html` (or `dist/index.html` for `/`)
  exists for each path, prints `15/15`, and exits 1 on any miss (R3).
- `scripts/check-dist.mjs`: assertions on the built HTML. It exits 1 on the first failure, with
  the requirement number.
  - R6: `/img/descendant-{1,2}.png` are referenced and exist in `dist/img`, and the Tableau
    iframe src is present.
  - R7: the alive post has no `<script`, contains `render(` inside a `<pre`, and no `react` or
    `react-live` chunk is in `dist/_astro`.
  - R8: every attribute of the contact form.
  - R9: `dist/sw.js` exists and contains `unregister`, and no page contains
    `serviceWorker.register`.
  - R10: each page has `og:title`, `twitter:card`, canonical and `application/ld+json`, the index
    has a `WebSite`, posts have `BlogPosting`, and `sitemap-index.xml` exists.
  - R11: no `UA-141571270`, `googletagmanager`, `google-analytics`, `metomic` or `Manage Cookies`
    anywhere in `dist`.
  - R13: `manifest.webmanifest` parses and has name and icons.
- `.github/workflows/ci.yml`: on push and pull_request, ubuntu-latest, `actions/checkout@v4`,

3. **Static assets and Netlify.** `git mv static public`, edit robots.txt, add `sw.js`,

## Rollback

- **Code:** `git revert <ship sha>` on `master` restores the Gatsby site, and Netlify rebuilds
  it with the old settings. The old Gatsby build may no longer succeed on Netlify, though, so the
  practical rollback is a **Netlify dashboard → Deploys → the last Gatsby deploy → "Publish
  deploy"**, which re-serves the previous build output without rebuilding.
- **Not covered by revert:**
  - Browsers where the kill-switch `sw.js` already ran have unregistered the old worker. That
    is harmless: they just fetch the site normally.
  - Netlify UI build settings aren't changed by this plan; `netlify.toml` overrides them while
    present, and a revert removes it.
  - Branch protection and Renovate's automerge setting on GitHub (if enabled for R16) stay as
    set: undo them in GitHub → Settings → Branches.
